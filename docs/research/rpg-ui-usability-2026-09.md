# Rovenfall RPG UI·관리 웹 콘솔 사용성 비교 조사 (2026-09)

## 결론

Rovenfall은 이미 플레이어용 인벤토리 탭, 한 단계씩 돌아가는 Back, 키보드 포커스·낭독,
서버 한정 검색, 기술 정보 분리라는 좋은 토대를 갖고 있다
([플레이어 GUI 계약](../player-gui.md), [관리 GUI 계약](../admin-gui.md)). 다음 개선의
핵심은 기능을 더하는 것이 아니라 **위험한 관리자 변경을 읽기→미리보기→확정으로
분리**하고, 플레이어가 현재 목표·화면 위치·키보드 조작을 한눈에 알게 만드는 것이다.

> 구현 상태(2026-09-03): 이 조사 직후 외부 관리 작업의 서버 미리보기·별도 확정,
> 위험 작업 재입력, 모달 포커스 관리, 성공 결과의 감사 로그 연결, 웹/인게임 공통
> 단축키를 적용했다. 아래의 “조사 시작 시 기준선”과 관찰 표는 개선 전 상태를 기록한다.

가장 시급한 문제는 외부 웹 콘솔의 쓰기 동작이다. 현재 구현은 관리 양식의 첫 `submit`이
`POST /api/v1/actions`를 호출해 실제 작업을 실행하며, 모달은 `Escape`와 바깥 클릭으로
닫힌다([현재 구현](../../admin-web/app/page.tsx)). 이는 서버 인벤토리 관리 화면이 요구하는
“서버 생성 미리보기, 최신 스냅샷 재검증, 두 번째 명시적 확인”과 다르다
([관리 GUI 계약](../admin-gui.md)). 따라서 P0는 웹 콘솔을 동일한 안전 경계로 맞추는 일이다.

## 범위·방법

- 기준일: 2026-09-03. Rovenfall의 현재 문서와 `admin-web/` 소스, 그리고 공개된
  **공식 문서·공식 게임 가이드·공식 소스 저장소**만 읽었다. 블로그, 사용자 위키,
  영상, 커뮤니티 리뷰는 근거에서 제외했다.
- Minecraft/NeoForge의 화면과 키보드 관례, Minecraft 퀘스트 모드, 대표 RPG의 정보
  탐색·키 설정, 그리고 운영 콘솔의 검색·권한·확인·감사 UX를 비교했다. 아래 제안은
  각 제품을 그대로 복제하라는 뜻이 아니라 Rovenfall의 서버 권위·감사·한정 조회
  원칙 안에서의 적용안이다.
- ‘현재 상태’는 제품 추측이 아니라 Rovenfall 문서 또는 현재 소스를 근거로 했다.
  구현 범위와 일정은 이번 조사에 포함하지 않는다.

## 조사 시작 시 기준선

### 인게임 RPG UI

Rovenfall은 일반 생존 인벤토리에 Overview·Land·Travel·Skills·Shops·Journey를 두고,
Journey에서는 자연어 상태·보상 미리보기·서버가 정한 다음 한 단계를 보여 준다. 키보드
사용자는 화살표로 슬롯 포커스를 옮기고 `Enter`/`Space`로 실행하며, Back은 한 단계만
되돌아간다([플레이어 GUI 계약](../player-gui.md)). 이는 “명령어/ID 대신 현재 할 일”이라는
방향에 이미 부합한다.

다만 이 계약은 화면별 항목·다음 단계에는 강하지만, **어느 계층에 있는지**, **어떤
키가 가능한지**, **여러 후보 중 무엇을 우선 추적할지**를 공통으로 짧게 설명하는
규칙은 명시하지 않는다. `Journey`의 활성 추적은 한 항목만 표시하고 화면이 열리면
사라진다([활성 여정 추적](../player-gui.md#active-journey-tracker)).

### 외부 관리자 웹 콘솔

웹 콘솔은 로컬 루프백·세션 탭 토큰을 사용하고, 현황·사용자·감사·경제·클레임·상점
조회와 역할/잔액/되돌리기 작업을 제공한다
([운영 콘솔 안내](../operations/admin-console.md)). 소스상 전역 검색은 280ms 후 자동
조회되며, 감사 화면에는 사용자·작업·결과·시간 범위의 별도 필터와 Apply 버튼이 있다
([Console 상태와 조회](../../admin-web/app/page.tsx)).

조사 시작 시에는 다음 사용성/안전 불일치가 있었다.

| 관찰 | 영향 | 근거 |
| --- | --- | --- |
| 관리 양식의 `Confirm and run`은 미리보기 없이 곧바로 POST한다. | 잘못 붙여넣은 UUID·금액·역할을 검토할 마지막 단계가 없다. | [ActionDialog](../../admin-web/app/page.tsx) |
| 모달이 `Escape` 및 배경 클릭으로 닫힌다. | 일반 상세에는 편하지만, 쓰기 양식에서 입력 손실과 ‘취소’의 모호함을 만든다. | [Modal](../../admin-web/app/page.tsx) |
| 검색은 모든 비감사 목록에 공통 입력 하나를 재사용한다. | 현재 검색 대상/적용 시점이 화면별로 명확하지 않고, 감사의 구조화 필터와 모델이 다르다. | [Console 상태와 조회](../../admin-web/app/page.tsx) |
| 성공 후 토스트는 거래 ID 축약값만 보여 준다. | 수행자·대상·전후값·감사 증거로 바로 이동하는 복구 흐름이 약하다. | [완료 토스트](../../admin-web/app/page.tsx) |

## 비교 조사

### 1. Minecraft·NeoForge: 화면은 해상도/GUI 배율과 보조기기에 맞고, 단축키는 충돌 문맥을 가져야 한다

NeoForge는 화면 초기화 시 게임의 상대 폭·높이를 사용하고, 창 크기 변경 때 다시
초기화된다고 설명한다. 상호작용·렌더·낭독을 모두 포함하는 위젯 경로도 별도로
제공한다([NeoForge Screens](https://docs.neoforged.net/docs/1.21.1/gui/screens/)). 따라서
Rovenfall의 RPG 카드/관리 화면은 고정 슬롯 배치만 통과 기준으로 삼지 말고, GUI 배율
변경 후에도 제목·경로·포커스·현재 페이지·확인 버튼의 읽는 순서를 유지해야 한다.

NeoForge 키 매핑은 `UNIVERSAL`, `GUI`, `IN_GAME` 충돌 문맥을 구분하고, GUI 안에서는
매핑의 활성 여부를 검사해 처리하도록 한다
([NeoForge Key Mappings](https://docs.neoforged.net/docs/1.21.3/misc/keymappings/)). 즉
`Esc`, `Enter`, 화살표, `Tab`은 화면의 기본 동작을 존중하고, 새 단축키는 GUI 문맥의
변경 가능한 키 매핑으로 등록하는 편이 안전하다. Minecraft Education의 공식 조작
가이드는 `E`=인벤토리, `Esc`=일시정지라는 기본 기대도 확인한다
([공식 Controls Guide](https://education.minecraft.net/lessonsupportfiles/Controls-Guide-no-background.pdf)).

**Rovenfall 적용:**

- 모든 2단계 이상 화면의 제목 아래에 `Journey › Requests › 상세`처럼 짧은 경로와
  `Esc: 뒤로 / [키]: …` 힌트를 한 줄로 둔다. `Esc`는 입력 중인 검색을 지우거나
  구매를 확정하지 않고, 먼저 같은 화면의 취소/뒤로 동작을 수행한다.
- `다음 여정`, `새로고침`, `필터 전환`, `고급 정보`처럼 자주 쓰는 보조 동작은
  GUI-문맥 키 매핑으로 제공하고, 화면 안의 ‘키 도움말’에서 현재 배정을 표시한다.
  이미 문서화된 화살표·`Enter`·`Space`·`Tab` 동작은 유지한다.
- UI 검증은 해상도뿐 아니라 GUI 배율 변경, 키보드만 사용, 낭독 순서, 포커스가
  Back/Refresh/Previous/Next 사이에서 빠지지 않는지를 포함한다. 이는 NeoForge의
  재초기화·낭독 위젯 모델에 직접 대응한다.

### 2. Minecraft 퀘스트 UI: 검색·장(章)·고정 추적·이력은 큰 퀘스트 그래프의 인지 부하를 낮춘다

FTB Team의 공식 FTB Quests 소스는 퀘스트 화면에 검색, 장 이전/다음, 최근 중심으로
되돌리기, 확대/축소/재중심, 패널 보기 이력(`Backspace`)을 위한 키를 제공한다
([공식 번역/키 참조](https://github.com/FTBTeam/FTB-Quests/blob/main/common/src/main/resources/assets/ftbquests/lang/en_us.json)).
또한 자동 고정 추적은 마지막으로 본 장 또는 전체 퀘스트 책을 범위로 삼고, 추적 패널의
크기·표시 대상을 사용자가 조절할 수 있다
([공식 변경 기록](https://github.com/FTBTeam/FTB-Quests/blob/main/CHANGELOG.md)).

이 사례의 중요한 점은 복잡한 노드 그래프 자체가 아니라 다음 네 가지다.

| FTB Quests에서 확인되는 패턴 | Rovenfall에 맞춘 결론 |
| --- | --- |
| 검색·장 이동·재중심·이력을 별도 키로 제공 | Journey가 목록형을 유지하더라도, 검색 결과에서 상세를 열었다가 목록의 같은 필터/페이지/포커스로 돌아가게 한다. |
| 잠긴 퀘스트 아이콘과 의존성에 따른 가시성 설정 | 숨겨야 할 비밀은 계속 숨기되, 이미 보이는 잠금 항목은 ‘왜 아직 불가한가’와 다음 선행 목표를 자연어로 설명한다. |
| 자동 고정 범위를 최근 장으로 제한 가능 | 활성 Journey 한 개는 유지하되, ‘현재 장/전체/숨김’ 표시 범위를 선택하게 하면 HUD가 목표 나열로 변질되지 않는다. |
| 알림을 toast/chat/action bar/없음으로 선택 | 완료 알림은 기본 toast 한 방식으로 시작하고, 반복 의뢰가 늘면 알림 위치/강도를 접근성 설정으로 분리한다. |

FTB Quests는 `Ctrl+F`를 검색 단축키로 사용하고, modifier 키 두 번 누르기로 검색을
여는 방식은 키보드 이벤트 문제 때문에 제거했다
([공식 변경 기록](https://github.com/FTBTeam/FTB-Quests/blob/main/CHANGELOG.md)). Rovenfall도
‘Shift 두 번’ 같은 숨은 제스처보다, 키 설정에서 보이고 충돌을 검사하는 명시적 GUI
단축키를 택해야 한다.

### 3. 대표 RPG: 정보는 카테고리→필터→상세로 좁히고, Esc와 키 재설정을 탈출구로 쓴다

FINAL FANTASY XIV의 공식 UI Guide는 UI를 조정할 수 있는 대상으로 다루며, 초보자
도움말은 검색어 입력→주제 찾기→내용 확인의 흐름을 제시한다. 인벤토리/장비/시장 등
큰 주제마다 `All`과 하위 필터를 제공한다
([FFXIV 공식 UI Guide](https://na.finalfantasyxiv.com/uiguide/)). 공식 데이터베이스도
키워드 검색과 퀘스트·업적·상점 등 카테고리를 함께 둔다
([FFXIV 공식 Eorzea Database](https://na.finalfantasyxiv.com/lodestone/playguide/db/)).

The Elder Scrolls Online의 공식 지원 문서는 `Esc` 메뉴의 Controls > Keybindings에서
핫키 목록을 보고 재할당한다고 안내한다
([ESO hotkeys](https://help.elderscrollsonline.com/app/answers/detail/a_id/2534/),
[ESO hotkey assignment](https://help.elderscrollsonline.com/app/answers/detail/a_id/2535/)).
Blizzard의 공식 지원도 WoW에서 `Esc`로 메뉴를 열고 Key Bindings/Interface로 들어가는
절차를 사용한다([WoW 지원 문서](https://us.support.blizzard.com/de/article/45460)).

**Rovenfall 적용:**

1. Journey·Skills·Travel의 첫 화면은 ‘가장 할 만한 다음 행동’ 한 장을 먼저 보여 주고,
   그 아래에서 상태/지역/유형으로 좁힌다. 모든 카드의 상세를 처음부터 같은 밀도로
   노출하지 않는다. 이는 Rovenfall의 현재 다음 단계 카드 원칙을 확장하는 것이며,
   FFXIV의 카테고리→필터 모델과 일치한다.
2. 검색은 결과가 0개일 때 “검색어를 바꾸라”만 말하지 말고 현재 필터, 검색 범위,
   잠금/공개 정책 때문에 제외된 경우를 짧게 분리해 설명한다. 비밀 좌표·식별자는
   보내지 않는 현 정책은 유지한다.
3. Escape는 항상 예측 가능한 탈출구여야 한다. 다만 FFXIV/ESO/WoW의 사례는
   `Esc`가 보편적인 메뉴·키 설정 진입점임을 보여 주는 것이지, Rovenfall이 인게임
   메뉴를 대체해야 한다는 근거는 아니다. Rovenfall은 기존 Minecraft `Esc` 기대와
   충돌하지 않는 ‘현재 오버레이 닫기 또는 한 단계 Back’으로 제한한다.

### 4. 관리 콘솔: 검색 가능한 감사 증거, 최소 권한, 영향이 보이는 확인이 함께 있어야 한다

GitHub 조직 감사 로그는 소유자만 접근 가능하며, 날짜 범위를 포함한 구조화된 검색
연산자로 조회한다. 각 이벤트는 수행 조직·수행자·영향 대상·작업·시각 같은 정보를
보여 준다([GitHub 공식 감사 로그 조회](https://docs.github.com/en/organizations/keeping-your-organization-secure/managing-security-settings-for-your-organization/reviewing-the-audit-log-for-your-organization)).
Rovenfall도 감사 화면의 사용자·작업·결과·시간 필터를 이미 갖고 있으므로, P0는 새
검색 문법을 만드는 것이 아니라 **작업 성공 화면에서 그 정확한 감사 증거로 연결**하는
것이다.

AWS IAM은 최소 권한을 ‘업무에 필요한 권한만 부여’하는 모범 사례로 정의한다
([AWS 최소 권한](https://docs.aws.amazon.com/IAM/latest/UserGuide/getting-started-reduce-permissions.html)).
또한 콘솔에서 영구 삭제 전 최근 사용 활동을 검토하고, 검색으로 대상을 좁힌 뒤,
확인 절차를 거치도록 안내한다
([AWS IAM 정책 삭제](https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies_manage-delete-console.html)).
사용자의 실제 콘솔 탐색에는 목록/조회 권한도 필요함을 별도로 명시한다
([AWS 콘솔 권한](https://docs.aws.amazon.com/IAM/latest/UserGuide/access_permissions-required.html)).

**Rovenfall 적용:**

- 역할·지급·차감·되돌리기 화면을 `입력 → 서버 미리보기 → 확정`으로 분리한다.
  미리보기에는 수행자 역할, 대상(표시명+축약 UUID), 동작, 전후 잔액/역할/영수증,
  온라인 필요 여부, 보상 옵션, 사유, 되돌릴 수 있는지, 생성될 거래 ID를 표시한다.
  확정은 그 스냅샷 revision/유효 기간을 서버에서 다시 검증한다.
- 역할 변경/차감/되돌리기는 미리보기에서 `Escape`·배경 클릭으로 닫지 않는다.
  **취소** 버튼과, 입력이 사라진다는 명시가 있는 닫기 확인을 둔다. 확정 단계에서는
  기본 포커스를 안전한 취소에 두고, 위험도가 높은 작업은 대상 표시명 또는
  `실행`을 다시 입력하게 한다. 이는 AWS의 영향 검토·확인 패턴을 Rovenfall의
  기존 서버 스냅샷 계약에 맞춘 것이다.
- 조회 권한과 변경 권한을 UI에서도 분리한다. 읽기 전용 역할에는 버튼을 단순히
  숨기기보다 ‘필요 역할’과 가능한 읽기 작업을 명시하고, 서버 권한 검사는 계속
  매 요청 시 수행한다. 현재 인게임 관리 계약의 역할별 가시성과 서버 재검증을
  웹에도 동일하게 적용한다([관리 GUI 계약](../admin-gui.md)).
- 성공 토스트는 `감사 기록 보기`와 `대상 보기` 링크를 포함하고, 실패/거부도
  요청 ID·사유·재시도 가능 여부를 남긴다. 목록 필터는 URL에 반영해 새로고침과
  링크 공유 후에도 같은 읽기 맥락을 복원한다. 토큰은 URL에 절대 넣지 않는다.

## 우선순위 체크리스트

### P0 — 운영 실수 방지와 접근 가능한 기본 흐름

- [x] 외부 웹 콘솔의 모든 쓰기 작업을 **입력 → 서버 생성 미리보기 → 별도 확정**으로
  전환한다. 미리보기/확정 모두 역할·대상·현재 상태·revision을 서버에서 검증한다.
- [x] 역할 변경, 잔액 차감, 거래 되돌리기에는 영향 요약(대상, 전후값, 온라인 조건,
  되돌림/보상 상태, 사유, 감사 ID)을 보여 주고, 명시적 취소와 위험 작업용 재입력을
  둔다. `Esc`/배경 클릭으로 확정 단계가 조용히 사라지지 않게 한다.
- [ ] 성공·거부·실패 결과에 정확한 감사 기록/대상 상세로 가는 링크를 제공한다.
  사유·수행자·대상·시각·결과를 바로 검토할 수 있게 한다.
- [x] 웹 모달에 초기 포커스, 포커스 트랩, 닫은 뒤 원래 실행 버튼으로의 포커스 복귀,
  명확한 `aria-labelledby`를 추가한다. 키보드만으로 로그인·검색·필터·미리보기·취소·확정을
  완료할 수 있게 한다.
- [ ] 인게임 화면에서 `Esc`/Back의 규칙을 공통화하고, 화면 경로와 현재 가능한 키를
  짧게 표시한다. Minecraft 기본 `Esc`/`E` 기대 및 NeoForge GUI 키 충돌 문맥을 보존한다.

### P1 — 정보 탐색과 일상 작업 속도

- [ ] Journey/Skills/Travel에 ‘권장 다음 행동 → 상태/유형 필터 → 상세’ 순서를 일관되게
  적용하고, 상세에서 Back하면 기존 검색어·필터·페이지·포커스로 돌아오게 한다.
- [ ] Journey에 서버 한정 검색과 ‘진행 중/가능/완료/잠김’ 필터를 추가한다. 잠김 항목은
  공개 가능한 선행 조건과 다음 행동만 설명하고 비밀 데이터는 보내지 않는다.
- [ ] 활성 여정 추적에 `현재 장만 / 전체 가능 항목 / 숨김`의 표시 범위와 크기 옵션을
  제공한다. 기본값은 지금처럼 한 개의 다음 목표로 유지한다.
- [x] 웹 전역 검색에는 현재 대상 범위(사용자/경제/클레임/상점)를 표시하고, 감사에는
  구조화 필터·적용·지우기·활성 필터 요약을 둔다. 검색/필터/페이지를 URL의 비밀 없는
  상태로 보존한다.
- [ ] 키보드 단축키는 NeoForge GUI 문맥의 재할당 가능한 키 매핑으로 제공하고, 화면 안
  키 도움말에 표시한다. 숨은 연타 제스처는 추가하지 않는다.

### P2 — 개인화·운영 관찰성의 완성도

- [ ] 플레이어가 HUD 추적 알림 위치·크기·완료 알림 방식(toast/채팅/액션 바/끄기)을
  선택하게 하되, 서버가 소유하는 진행/보상 데이터는 클라이언트 설정과 분리한다.
- [ ] 웹 콘솔에 저장 가능한 읽기 전용 감사 검색 프리셋(예: 최근 거부, 특정 플레이어,
  경제 되돌림)과 결과 수/스캔 한계/잘림 표시를 추가한다.
- [ ] 좁은 화면에서 표는 우선 열을 유지한 카드/상세 드릴다운으로 전환하고, 고급 ID·좌표·
  해시는 명시적 ‘기술 정보’에서만 복사 가능하게 한다.
- [ ] GUI 배율, 창 리사이즈, 키보드 전용, 낭독, 긴 한국어/영어/일본어 문자열, 빈 결과,
  권한 변경·스냅샷 노후화·네트워크 실패를 포함한 UI 회귀 시나리오를 릴리스 검증에
  추가한다.

## 채택 시 지켜야 할 경계

- 플레이어 검색/추적 편의가 미발견 장소, 제한 토지, 포털 좌표, raw 식별자, 다른
  차원의 상태를 클라이언트에 더 보내는 이유가 되어서는 안 된다. 현재의 서버 필터와
  기술 정보 분리 원칙을 유지한다([플레이어 GUI 계약](../player-gui.md)).
- 웹 콘솔의 편의 기능이 권한 검사를 브라우저에 위임해서는 안 된다. 역할은 화면을
  열 때와 미리보기/확정 때 모두 서버에서 재검증하고, 모든 결과를 기존 감사 경로에
  남긴다([관리 GUI 계약](../admin-gui.md)).
- P0는 신규 도메인·새 화폐·새 데이터베이스가 아니라 기존 관리 API와 감사 모델의
  상호작용을 안전하게 만드는 작업이다. 따라서 RPG 콘텐츠 확장보다 먼저 처리하는
  것이 적절하다.
